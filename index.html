步驟指引：完整設定流程

依序完成以下五大步驟，即可順利讓你的網站上線運作。

5 個步驟完整解析
1

安裝 Git 與註冊 GitHub 帳號 準備階段

Git 是本地版本控制工具，GitHub 則是代碼代管平台。Render 將會直接連結你的 GitHub 儲存庫抓取代碼。

A. 安裝 Git 工具
  • Windows：前往 git-scm.com 下載並安裝（安裝過程一路點 Next 即可）。
  • macOS：終端機執行 xcode-select --install 或透過 Homebrew 安裝。
  • 安裝完成後打開終端機 (PowerShell / Terminal)，輸入 git --version 確認安裝成功。
B. 配置全域使用者資訊 (必要一次性設定) 
git config --global user.name "你的名字或暱稱"
git config --global user.email "你註冊GitHub的信箱"
2

專案結構與雲端部署必備文件 關鍵細節

Render 需要知道該如何安裝依賴 (Build Command) 以及如何啟動伺服器 (Start Command)。根據你的框架，目錄中必須具備特定檔案。

專案根目錄結構要求
Python 專案要求
強烈建議： 專案內必須建立 .gitignore，忽略如 __pycache__/、node_modules/、虛擬環境目錄與含有機密金鑰的 .env 檔案！
3

在 GitHub 建立 Repository 並推送本地代碼 代碼上傳

登入 GitHub 建立一個全新的儲存庫 (建議設為 Public 或 Private 皆可)，並將本地專案 push 上去。 

# 1. 進入你的專案目錄並初始化本地 Git 倉庫
git init

# 2. 將所有檔案加入暫存區
git add .

# 3. 提交第一個版本記錄
git commit -m "feat: initial commit for deployment"

# 4. 指定主分支名稱為 main
git branch -M main

# 5. 連結到你在 GitHub 上建立的儲存庫 (請替換為你的網址)
git remote add origin https://github.com/你的帳號/你的專案名稱.git

# 6. 推送至 GitHub
git push -u origin main
4

註冊 Render 並授權連結 GitHub 雲端連接

前往 render.com 點選「Get Started for Free」，直接使用 GitHub 帳號快速登入。

① 免密碼一鍵登入

點擊 "Sign in with GitHub"，免手動輸入帳號密碼，並同時授權 Render 存取代碼庫。

② 儲存庫權限授權

可以選擇 "All repositories" 或只允許 Render 存取特定指定的專案庫 (Only select repositories)。

③ 進入 Dashboard

授權完畢後即可直接抵達 Render 控制台，準備新增 Web Service 或 Static Site。

5

建立 Web Service、設定環境變數與正式部署 上線完成

點擊右上角「New +」按鈕，選擇 Web Service（若是純 HTML/JS 則選 Static Site）。

設定欄位 (Field) 說明與填寫範例 特別注意事項
Name 你的服務名稱 (例如 my-api-app) 會決定你的預設網址：my-api-app.onrender.com
Region 伺服器節點 (建議選 Singapore (新加坡) 或 Oregon) 新加坡節點對台灣/亞洲地區連線延遲最低
Branch main 只要向此分支 git push，Render 就會自動重新發布
Build Command pip install -r requirements.txt 建置依賴項目的指令
Start Command gunicorn app:app 常駐背景伺服器啟動命令
Instance Type Free ($0 / month) 512 MB RAM, 0.1 CPU, 15 分鐘無連線會自動休眠
通訊埠 (PORT) 設定核心觀念【新手最容易踩坑！】

在本地開發時我們常綁定 localhost:5000 或 127.0.0.1:8000。 但在 Render 雲端主機上：

  • 主機 IP 必須監聽 0.0.0.0，不可監聽 127.0.0.1 (否則外部流量進不來)。
  • Render 預設會指派動態通訊埠環境變數 $PORT (通常為 10000)。若使用 gunicorn 或 uvicorn，請確保綁定 0.0.0.0:$PORT 或讓 Render 自動偵測。

常見錯誤與排錯避坑指南 (Troubleshooting)

整理新手在 Git 與 Render 上最常遇到的 4 大錯誤與快速解決對策。

GitHub 自 2021 年起已停用純帳號密碼 push，請改用以下兩種方式之一：

  1. Personal Access Token (PAT)：進入 GitHub 點選右上角頭像 -> Settings -> Developer Settings -> Personal access tokens (classic) -> Generate new token，勾選 repo 權限，生成的代碼即為密碼。
  2. 使用 GitHub Desktop 或 VS Code 內建 Git 登入：點擊「Sign in with browser」，工具會自動處理 OAuth 授權，最省事。

這是最普遍的報錯！代表 Render 的健康檢查 (Health Check) 探針連不到你的伺服器，通常有兩個原因：

  • IP 綁定錯誤：代碼中監聽了 127.0.0.1，請改成 0.0.0.0。
  • Port 硬編碼：請讀取環境變數 os.environ.get('PORT', 5000) (Python) 或 process.env.PORT || 3000 (Node.js)。

Render 的 Free Web Service 在閒置 15 分鐘後會暫停容器以節省資源：

  • 作品集/Demo 演示：事先在要向他人展示前 1 分鐘自己先點開網址讓它喚醒。
  • 排程定時請求 (Ping)：若專案允許，可使用如 UptimeRobot 或 Cron-job 每隔 10~14 分鐘對你的網址發送一次 GET 請求維持活躍（請留意每月 750 小時免費運行時數上限）。
  • 若為純前端展示：建立為 Static Site，Static Site 永遠不休眠！

完全不用！這就是 CI/CD 的魔力。

只要你在本地端完成修改，並執行標準 Git 三部曲：

git add .
git commit -m "update: fix bug"
git push origin main

Render 會透過 Webhook 自動偵測到 main 分支的最新提交，並在背景自動觸發編譯與無縫熱重啟 (Zero-downtime deploy)。
